# PRODUCT.md

# Task API

## Goal
Build a small to-do CRUD API that can create, read, update, and delete tasks, test it through Swagger UI, and publish it to GitHub. The assignment requires an in-memory list rather than a database. Data loss after restart is expected.

## User
A developer learning backend fundamentals who needs to call the API from curl, a browser, or Swagger UI.

## Task model
```json
{
  "id": 1,
  "title": "Buy milk",
  "done": false
}
```

- `id`: integer generated by the server
- `title`: non-empty text
- `done`: boolean
- Start with 3 example tasks in memory.

## Required API

| Method | Path | Behavior | Success |
|---|---|---|---|
| GET | `/` | API metadata | 200 |
| GET | `/health` | `{"status":"ok"}` | 200 |
| GET | `/tasks` | List all tasks | 200 |
| GET | `/tasks/{id}` | Get one task | 200 |
| POST | `/tasks` | Create task; server sets next ID and `done=false` | 201 |
| PUT | `/tasks/{id}` | Update `title` and/or `done` | 200 |
| DELETE | `/tasks/{id}` | Remove task | 204 |

Root response:
```json
{"name":"Task API","version":"1.0","endpoints":["/tasks"]}
```

## Validation & errors
- Missing/empty title on POST → `400` JSON error.
- Invalid/empty PUT body → `400` JSON error.
- If PUT includes `title`, it must be non-empty.
- Unknown task ID → `404` JSON error.
- Example: `{"error":"Task 99 not found"}`.
- Never return an empty `200` for a missing resource.

## Documentation
Swagger UI is available at `/docs` and must list every endpoint with a short description. The full CRUD flow must work via “Try it out”.

## Delivery
Public GitHub repository with at least 6 meaningful stage commits and a README containing:
- purpose
- install/run instructions
- endpoint table
- one `curl -i` output
- Swagger screenshot

## Non-goals
No database, persistence, authentication, frontend, Docker, deployment platform, queues, caching, ORM, or microservices.

## Acceptance
The complete CRUD cycle works via curl and Swagger UI with required status codes:
`200`, `201`, `204`, `400`, `404`.
